# Linux 容器部署

主分支的 0.8 内置核心仍在开发，容器配置也尚未经过运行或升级验收，不作为已发布安装包。以下方式从当前源码构建镜像，不下载独立 frp 程序。

需要支持主机网络的 Linux Docker 和 Compose。在源码目录执行：

```sh
docker compose build
docker compose up -d
docker compose logs kurumifrp
```

配置使用主机网络，使服务端监听端口和代理端口直接属于主机网络命名空间；这些端口是否向外开放取决于实例配置和主机防火墙。工作台固定监听主机的 `127.0.0.1:9000`，如端口已占用，先在 `compose.yaml` 的服务中添加 `command: ["--data", "/data", "--listen", "127.0.0.1:9001"]` 并选择可用端口。远程设备应通过 SSH 端口转发访问该回环地址，不要将工作台直接发布到公网。

初始化完成后，在有权管理 Docker 的主机终端查看本地管理令牌：

```sh
docker compose exec kurumifrp /kurumi --data /data --show-token
```

令牌授予完整管理权限，不要将输出发送给其他人或写入共享日志。镜像以 UID/GID 65532 运行，不挂载 Docker socket，也不要求特权容器或额外网络管理能力。默认命名卷保留 `/data`；如改为绑定主机目录，请确保目录为 UID/GID 65532 可读写且其他账户不能读取。Docker 管理员和拥有主机文件访问权限的人员仍能读取数据和令牌。

默认镜像不包含 `nft`，也没有网络管理能力，因此不能使用工作台的 Linux 端口来源过滤功能；其他实例管理功能不需要为此增加容器权限。该过滤功能的运行前提和限制见[端口来源过滤](LINUX_FIREWALL.md)。

`docker compose stop` 会请求工作台关闭并等待已管理实例停止；超过配置的两分钟宽限期或异常退出可能留下 `manager.lock`。配置默认不自动重启容器：启动被锁阻止时，应先确认旧工作台及其管理的连接已退出，再按工作台提示处理锁。备份前可使用工作台的加密备份功能；停止或删除容器不会自动删除命名卷，但 `docker compose down -v` 会删除卷及其中数据。

镜像以源码运行方式构建，工作台内的原生安装包更新不可用于替换容器；更新时应取得新源码、重新构建镜像并重建容器。容器镜像及其中版本目前没有项目提供的已验证发布构建。
