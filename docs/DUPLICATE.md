# 复制实例与连接规则

此功能用于创建备用线路、迁移服务配置或复制相似的 frpc/frps 草稿，不需要重新输入复杂的连接参数。

- 在「运行实例」点击「复制实例」。可以选择同时复制关联规则，复制的规则默认全部停用；不会启动新的进程。
- 在「连接看板」点击「复制规则」，选择当前或其他 frpc 客户端作为目标。副本自动分配新 ID 和不重复的名称，默认停用。
- 在「连接规则」选择“批量复制”，可将多条规则复制到一个 frpc 客户端。主列表切换筛选时保留选择，并显示筛选外数量；可只保留当前筛选或清空全部。复制窗口显示总数及主列表、窗口各自筛选外的数量，确认时会再次提示，这些范围可能重叠。草稿变化时须刷新后重新选择；副本独立命名且全部停用。XTCP Visitor 的回退目标和完整回退链必须一并选择，回退会改为对应副本；缺失或循环依赖会使整批失败。之后启用规则时仍须先启用其回退目标。
- frpc 副本继承连接目标、源地址、连接超时、保活设置和已经加密的认证信息；自动启动保持关闭。创建后须确认服务端地址和令牌。
- frps 副本保留控制入口来源限制、保活等非监听配置，自动启动保持关闭，并自动选择不与已登记 frps、启用的 Visitor 冲突的 TCP 监听端口；HTTP/HTTPS、TCPMUX、KCP 和 QUIC 的附加监听默认关闭。请在编辑器里自行设置正确端口，且确认操作系统端口尚未被其他进程占用。
- STCP 副本在同一受保护状态数据库中复用原有加密密文，不经浏览器回传明文，复制后应核对配对关系。复制整个实例时保留关联规则原名；跨实例或同实例复制单条规则时自动添加 `-copy` 等后缀。
- TCP 规则的 Unix 套接字目标也会随规则复制；目标路径依然指向原位置，应按目标客户端实际环境核对。
- 不复制正在运行的进程、PID、日志、状态检查结果或服务器上的实际代理注册状态。所有改动采用一个配置修订提交，可从已有历史快照恢复。

后端 `POST /api/duplicate` 经过原有 Host/Origin、登录鉴权和 revision 乐观锁校验。示例请求：

```json
{"revision": 8, "kind": "instance", "id": "0123456789abcdef", "includeTunnels": true}
```

复制单条规则到其他客户端：`{"revision":8,"kind":"tunnel","id":"0123456789abcdef","targetInstanceId":"fedcba9876543210"}`。

批量复制：`{"revision":8,"kind":"tunnels","ids":["0123456789abcdef","fedcba9876543210"],"targetInstanceId":"0123456789abcdef"}`。响应中的 `ids` 按请求顺序返回新规则 ID，`rulesCopied` 为复制数量。目标必须是已有 frpc；规则 ID 重复、源规则不存在、数量超限、Visitor 命名空间不能安全保留或回退链不完整都会拒绝整批。加密凭据仍由本机状态库复制，不回传明文；不会启停运行实例。正常保存失败不会留下部分副本，请求断线时应刷新并核对结果，避免盲目重试。

复制仍使用完整状态校验与原子提交，超出 64 个实例 / 512 条规则、冲突或无效的请求不会改变数据库。管理器不探测、不预留实际操作系统端口，不调用 frp，也不新增外部服务或依赖。
