# 内置运行时与打包候选

当前改造供开发审阅，不是发行确认。工作台和 manager 的默认入口使用同进程的受限 frp v0.72.0，随工作台一起升级，不下载或执行独立 frpc/frps；旧的外部后端构建开关已移除。受限功能及其实现边界见 [隔离说明](../third_party/frp/KURUMI_ISOLATION.md)。

内置模式不创建外部核心管理目录，也不使用或覆盖已有外部核心选项和文件；外部核心下载与切换接口已移除。旧选项和未迁移的旧选择暂时保留在数据中，不参与内置实例的运行比较；其他相关遗留代码仍待清理。导出文件在缺少选择时使用空值，导入保留目标设备的旧外部核心选择。导入或恢复状态不重启实例。内部日志和注册状态按实例接入；部分依赖仍可能使用进程级日志。

启动请求成功只表示已接收：内置实例先显示“启动中”，引擎进入运行循环后才显示“运行中”并产生启动通知。客户端的信号发生在尝试登录之前，不代表连接、认证或代理注册成功；服务端的信号表示监听器已构造且工作循环已启动，不代表外部可访问。停止或引擎退出后显示“停止中”，只有清理完成后才允许替换该代次。状态是异步观察结果，极短的并发退出仍可能在下一次观察时才反映。远程节点协议 1 不包含过渡状态，实例启动或停止时该节点的状态查询会暂时返回不可用。

Windows 安装器和 Linux 原生包不再携带独立核心，许可分别包含于安装说明和包版权文件；便携包包含 `LICENSE-frp`。安装维护保留路径与数据所有权检查，Windows 如发现当前版本号已有旧式预置目录则拒绝覆盖，需使用新版本号。旧用户核心目录不会由此改造主动清除；Linux 包管理器可能按自身记录移除旧包拥有的文件。升级及卸载行为需要在隔离机器上验证，不能以静态审查代替。

发布工作流当前通过 `release` 作业的 `if: ${{ false }}` 明确禁用自动发布。完成验收并人工评审后，需恢复原有仅 main 分支 push 或手动触发时运行的条件，并保留版本、附件和已有发布检查。验收应覆盖对应平台和架构的真实 TCP、UDP、HTTP(S)、STCP、XTCP、Visitor、健康检查、动态端口及与官方服务端的互通；并验证多个客户端与服务端并发、日志隔离、启动失败、停止超时、异常终止后恢复、自动恢复，以及 Windows 安装升级卸载、Linux DEB/RPM 安装升级移除和便携包。特别是 `RuntimeInstance.Wait` 返回后资源是否均已释放，现有代码与交叉编译均不能证明。

交叉编译成功仅表示对应目标能够生成可执行文件，不证明硬件、系统环境或数据路径运行正常。本候选没有通过上述真实运行与生命周期验收，不应发布。
