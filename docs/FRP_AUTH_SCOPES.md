# frp 附加认证范围

实例编辑器中的「frp 附加认证范围」对应 frp 的 `auth.additionalScopes`。默认两项均关闭，保持原有行为；修改的是实例草稿，需启动或重启实例后生效。

- `HeartBeats`：客户端在心跳中提供认证信息，服务端验证该信息。
- `NewWorkConns`：客户端在新工作连接中提供认证信息，服务端验证该信息。

服务端启用某项后，连接该服务端的每个客户端也需要启用对应项并配置相同的 frp 令牌。否则，心跳可能被拒绝，或工作连接无法建立。客户端开启而服务端未开启时，服务端不会因该选项进行对应的额外校验。跨版本或连接外部 frp 时应先确认对方支持这些标准配置，并安排两端配置更新。

两项都使用实例原有的共享 token 认证方式，不创建每账户凭据，也不能识别账户或作为配额、计费依据；它们不替代 TLS、访问控制或其他网络保护。

共享令牌为空时，这些设置无法提供有效的密钥保护；请为 frpc 和 frps 配置相同的非空 frp 令牌。

frpc 和 frps 的 TOML 导出会包含已启用的范围；两项都关闭时不写该字段。TOML 导入识别 `auth.additionalScopes` 字符串数组中的 `HeartBeats` 和 `NewWorkConns`，对无法保留的其他值报告问题，避免静默丢弃。

启用后，新字段会保存在本机配置及其历史中。不能识别这些字段的旧版工作台可能拒绝读取配置；请保留原文件，使用支持这些设置的版本或兼容的旧备份，不要用旧版覆盖新配置。
