# frp 连接的 TLS 证书

管理员可在客户端或服务端实例草稿中填写 frp 原生的 TLS 证书、私钥和可信 CA 文件路径。证书与私钥必须同时填写或同时留空；每个非空路径必须是工作台所在系统可识别的绝对路径，长度最多 1024 字节，不能包含控制字符或花括号。这里只保存路径，不上传、生成、复制或导出证书及私钥文件。文件须为 PEM 格式，工作台运行账户必须有读取权限；私钥应妥善保护。

客户端的证书和私钥供 frps 要求客户端证书时使用；客户端的 CA 用来验证服务端证书。可同时启用系统信任库和 CA 文件，二者共同作为信任来源。两者都未设置时，默认仍是加密连接但不验证服务端证书。设置 CA 或系统信任库后，证书须匹配连接地址；连接地址与证书名称不同时，可填写 TLS 服务端名称，使用不含端口的 DNS 名称或 IP。单独填写名称不会启用证书验证。客户端关闭 TLS 时不能配置证书、私钥、CA 或服务端名称。

服务端的证书和私钥用于向 frpc 证明服务端身份；留空时沿用 frp 自动生成的证书。服务端的 CA 是**验证客户端证书**的信任库：设置后，TLS 连接必须提供并通过验证的客户端证书，且不能允许明文 frp 连接。客户端若验证服务端，通常需要服务端使用可被其信任、名称匹配的证书；自动生成的临时证书不自动成为客户端的可信证书。

这些选项作用于 frpc 与 frps 的 frp 连接，不是工作台网页的 HTTPS、登录证书或账户身份。服务端客户端证书 CA 不验证访问 TCP/UDP 代理端口或 HTTP(S) 虚拟主机的公网用户，也不实现账户额度。配置不会打开新的监听端口或改变远程访问设置；现有 frp 共享令牌认证仍然有效。

保存仅更新草稿，配置修改后需重新应用实例。草稿校验检查路径形式、证书和私钥是否成对及 TLS 选项冲突，不读取文件，也不证明证书有效、双方名称匹配或网络可达。内嵌 frps 构建服务时加载证书和 CA；frpc 建立连接时加载。文件缺失、权限不足、PEM 无效或证书与私钥不匹配会导致启动或连接失败；替换文件不会保证已建立的连接立即使用新内容，重新应用实例可明确生效。

TOML 导入和导出使用 `transport.tls.certFile`、`transport.tls.keyFile`、`transport.tls.trustedCaFile`，客户端还支持 `transport.tls.serverName` 和 `transport.tls.useSystemCa`。相对路径无法确定原配置文件的基准目录，导入时须先改成当前系统的绝对路径。实例复制、配置导出和备份保留路径，但不包含文件；换机器须自行准备文件并核对路径。不同操作系统的绝对路径可能不兼容，配置或备份恢复可能因此被拒绝；可先在源环境移除或修改路径后重新导出，再在目标环境配置。配置预览、历史和导出文件也可能显示本机路径，请按需要保护。旧版本可能不认识这些新增字段，回退前请保护配置和历史，避免用旧程序覆盖。

自定义运行后端只有声明并实现原生 TLS 文件设置后，才能校验或启动包含这些设置的实例；使用系统信任库仍需相应的独立能力声明。默认内嵌运行时支持这些选项，真实证书和协议互通仍需在目标环境验收。
