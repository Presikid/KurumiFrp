# HTTP 代理自定义头

HTTP 规则可分别设置请求头和响应头，对应 frp 的 `requestHeaders.set` 与 `responseHeaders.set`。它们由 frps 的 HTTP 代理应用；目标服务、客户端及中间代理可能看到相应头值，特殊头的效果仍受 frp 和 HTTP 实现限制。Host 改写请使用已有的 Host 重写字段。

每个方向最多 32 项，每个客户端实例合计最多 128 项；名称最多 128 字节，按 HTTP 字段名规则校验，并在同一方向内不区分大小写地拒绝重复。值必须是有效 UTF-8 HTTP 字段值，最多 1024 字节，可为短值或空值；不接受 CR、LF 等不合法控制字符。请求头与响应头可使用相同名称。

## 编辑与保密

头值按本地凭据加密保存，普通状态、配置预览和差异不返回明文。编辑时已保存值不回显：保留已有名称并留空表示保留值，输入新值替换；勾选“设为空值”明确设置空字符串，点击删除并保存明确删除该项。新项留空代表空字符串。名称改变超过大小写时须重新输入值或明确设为空值。HTTP 规则更换为其他协议前，须明确删除其全部自定义头。保存草稿后，运行中的实例需要重启才能应用。

日志与诊断使用工作台现有脱敏层处理头值及其常见编码形式。非空值少于 8 字节时，普通文本也可能碰巧命中：命中的整行或状态文本会替换为“内容已隐藏”的提示，而不是逐字符替换；空值不会作为匹配模式。短值可能导致大量信息被隐藏。该机制尽力保护工作台可控输出，不能保证外部 frp、远端服务或第三方依赖的独立日志一定不包含头值。

复制规则或复制客户端时，头项与其他加密凭据一同复制；历史快照、配置导入和加密备份保留它们。普通状态与快照预览只显示名称和是否有值，不展示密文或明文。JSON 配置导出包含数据密钥，应视为敏感文件；管理员明确确认的规则批量导出会把头值与其他凭据一同写入明文 TOML，应妥善保管。TOML 导入支持这两类头，预览不显示值；脱敏占位符 `<redacted>` 不可作为导入值。

## API 与兼容性

管理员通过现有 `POST /api/save` 保存规则。`requestHeaders` 和 `responseHeaders` 各为条目数组：省略整个字段保留原方向，发送空数组明确删除该方向全部条目；数组中已有名称省略 `value` 保留原值，`value: ""` 明确设置空值，非空字符串设置新值。新增或改变名称时必须提供 `value`，即使它是空字符串；数组中省略某个旧名称即删除该项。`null` 数组不作为删除。旧编辑器省略这些新字段时不会丢失已保存的头。

旧数据库没有这些字段时按空列表读取；不认识新字段的旧程序应拒绝读取并保留原文件。需要降级时，请在新版本中删除所有当前规则及保留快照中的相关头项，或使用兼容版本可读取的数据副本，避免旧程序覆盖新数据。
