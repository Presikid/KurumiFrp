# Linux 端口来源过滤

管理员可以手动为指定 TCP/UDP 目标端口应用 IP 或 CIDR 来源允许列表或阻止列表。此功能独立于服务端实例的控制入口来源限制：它在 Linux 内核的 nftables `prerouting` 链中处理入站流量，而不是只处理 frp 控制连接。默认不会更改任何内核规则；只有管理员在工作台明确保存并应用时才执行。

- 规则处理目的地址为本机、非回环接口上到达的 TCP/UDP 新连接，在 Docker 目的地址转换之前按原始目标端口匹配。已有连接、回环、从本机发出的流量及目的地不是本机的转发流量不在此功能的过滤范围内。允许列表未包含某个地址族时，该地址族的新连接也会被阻止。
- 端口范围必须明确填写，适用于 TCP 和 UDP；不会自动追踪 frps 动态分配的端口。同一端口上的其他服务也受影响。应用前应准备独立管理通道并确认范围。
- 需要 Linux、固定系统路径中的 `nft` 可执行文件和运行工作台进程的网络管理权限；工作台不会提权。此版本源码未经过各发行版、容器网络或内核的运行验收。
- 每个数据目录随机生成一个表名 `kurumi_<标识>`，只管理自己的表，不清空其他表。配置单独保存在数据目录的 `firewall.json`，不包含在可移植备份中；丢失该文件可能留下无法由工作台识别的规则表。界面显示表名，供管理员独立核对和恢复。
- 规则不会在工作台启动或系统重启时自动重放。重启、系统防火墙重载或其他管理工具可能移除或改变规则。界面中的成功只表示本进程最近一次应用命令返回成功，不证明此后规则仍存在。
- 配置先持久化再提交 nftables。如果写入后应用失败、中断或连接丢失，配置可能已更新而内核结果未知，旧规则也可能仍然存在。刷新配置后应由管理员独立核对实际规则，再决定是否手动重新应用；工作台不会自动重试。关闭功能并应用会移除本工作台管理的表。
- 此范围尚不包含 ASN/提供商过滤、社区地址列表或实时被阻止地址报告。
