# Linux 端口来源过滤

管理员可以为指定 TCP/UDP 目标端口应用 IP 或 CIDR 来源允许列表或阻止列表。此功能独立于服务端实例的控制入口来源限制：它在 Linux 内核的 nftables `prerouting` 链中处理入站流量，而不是只处理 frp 控制连接。默认不会更改任何内核规则；管理员手动应用后，可选择为单条规则启用自动刷新。

最多可设置 16 条规则，每条分别选择启用状态、端口、允许或阻止模式及来源列表；开启过滤时至少要有一条启用的规则。所有匹配同一端口的启用规则都会生效：连接必须通过每条允许规则，也不能命中任何阻止规则，因此重叠允许列表取交集而非并集。规则合计最多 4096 个来源项，停用的规则也计入上限，其端口和来源仍须填写有效值。旧版单条配置会在读取时显示，保存多条规则时迁移。停用全部过滤并应用会移除规则表，同时保留上次已保存的规则；编辑但尚未应用的更改不会随停用保存。

规则布局参考并改编自 [FRP Manager](https://github.com/Gogowwww/frp-manager) 的 `panel/firewall.go`，该项目使用 Apache License 2.0；本项目的改动及许可说明见 `internal/embedded/NOTICE`。

- 规则处理目的地址为本机、非回环接口上到达的 TCP/UDP 新连接，在 Docker 目的地址转换之前按原始目标端口匹配。已有连接、回环、从本机发出的流量及目的地不是本机的转发流量不在此功能的过滤范围内。允许列表未包含某个地址族时，该地址族的新连接也会被阻止。
- 端口范围必须明确填写，适用于 TCP 和 UDP；不会自动追踪 frps 动态分配的端口。同一端口上的其他服务也受影响。应用前应准备独立管理通道并确认范围。
- 需要 Linux、固定系统路径中的 `nft` 可执行文件和运行工作台进程的网络管理权限；工作台不会提权。此版本源码未经过各发行版、容器网络或内核的运行验收。
- 每个数据目录随机生成一个表名 `kurumi_<标识>`，只管理自己的表，不清空其他表。配置单独保存在数据目录的 `firewall.json`，不包含在可移植备份中；丢失该文件可能留下无法由工作台识别的规则表。界面显示表名，供管理员独立核对和恢复。
- 规则不会在工作台启动或系统重启时自动重放。重启、系统防火墙重载或其他管理工具可能移除或改变规则。界面中的成功只表示本进程最近一次应用命令返回成功，不证明此后规则仍存在。
- 配置先持久化再提交 nftables。如果写入后应用失败、中断或连接丢失，配置可能已更新而内核结果未知，旧规则也可能仍然存在。刷新配置后应由管理员独立核对实际规则，再决定是否手动重新应用；工作台不会自动重试。关闭功能并应用会移除本工作台管理的表。
- 可选的近期拦截记录默认关闭。启用并成功应用后，内核记录来源地址、TCP/UDP 协议和目标端口，每个地址族最多 1024 组，约一小时无新尝试后过期；规则重新应用、移除或系统重启会清除记录。单独的记录规则与丢弃规则分离，记录集合已满不应阻止丢弃。内核或 nftables 不支持动态集合时，启用记录的应用可能失败，结果需独立核对。管理员停留在页面时定期读取，读取失败或格式不支持会显示未知或部分结果；它不是完整审计日志，也不说明其他防火墙的拦截。
- 管理员可在拦截记录旁主动查询公网来源地址的路由网段和 AS。点击时会将该 IP 发送给 [RIPEstat Network Info](https://stat.ripe.net/docs/data-api/api-endpoints/network-info.html)；读取记录本身不会发送地址。结果来自 RIPE RIS 的周期性路由观测，可能滞后、不完整或有多个 AS，不等于连接发起者的身份；查不到结果不表示没有归属。查询不会保存或修改防火墙规则。
- 管理员可按 AS 号向 [RIPEstat Announced Prefixes](https://stat.ripe.net/docs/data-api/api-endpoints/announced-prefixes) 查询并把结果加入单条规则的可编辑来源列表；一次最多查询 16 个 AS，并发最多 4 个，任一查询失败或合并超限会拒绝整批。手动查询只更新页面草稿。该服务默认返回近两周达到其可见性门槛的路由通告，可能包含已撤销网段，也可能遗漏网段，不等同于提供商的完整或实时地址清单。所有规则的来源列表总计最多 4096 项；查询或合并超限时不会导入部分结果。查询会从运行工作台的系统连接 RIPEstat。
- 也可将已有的社区或自维护清单作为文本文件导入单条规则草稿。文件最多 256 KiB，每行填写 IP 或 CIDR，可用逗号分隔或 `#` 注释；任一无效项或数量超限会拒绝整个文件。文件仅在浏览器和本机工作台之间处理，应用前应人工核对来源与范围。
- 管理员也可手动输入公网 HTTPS 文本清单地址并加入规则草稿，格式及上限与文件导入相同。请求由运行工作台的系统发起，不使用代理或跟随重定向；DNS 解析结果必须全部为公网地址，请求使用验证过的地址连接并校验原域名的 TLS 证书。单次手动获取不会保存地址或应用结果；清单提供者可以改变内容，使用前应核对地址和范围。
- 查询或导入前可选择加入现有来源，或用新结果替换该规则的全部来源。替换可去除旧清单里已失效的地址；如同一规则混合了手工地址或其他清单，它们也会被替换。任一结果无效或合并后超限时，草稿保持不变。
- 单条规则可选保存一组 AS 号或一个公网 HTTPS 清单作为自动刷新来源，间隔 60–10080 分钟。请先查询或导入并核对初始列表，再手动保存并应用；成功后按间隔获取新结果，替换该规则的全部来源并重新应用，因此手工地址或其他清单也会被替换。任一查询失败、空结果或超限时保留旧列表；网络查询失败约五分钟后重试。刷新期间若配置已变化则丢弃旧结果。结果写盘后如果持久化或应用未确认，自动刷新暂停，需核对并手动重新应用。工作台或系统重启后也需先手动重新应用，自动刷新才恢复。自动应用会清除近期拦截记录；此功能不保证来源数据的完整性，也不会自动发现提供商地址。
