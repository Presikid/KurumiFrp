# 按实例查看实时运行日志

运行记录页面保留实例选择、关键词筛选和配置变更记录。对正在运行且有 `runId` 的实例，页面优先使用 `GET /api/logs/stream?id=<实例ID>&runId=<运行代次>`；浏览器不支持 SSE、连接失败或尚未启动时使用原有 `GET /api/logs?id=<实例ID>` JSON 轮询。实时连接断开后，页面继续轮询并以 1 秒起、最多 30 秒的退避间隔重连；页面隐藏、切换实例或页面、登出时关闭旧流。手动刷新会重新同步。状态仍独立轮询，以发现运行代次和实例列表变化。

“导出显示内容”将当前实例、运行代次和筛选条件下已显示的日志保存为 UTF-8 文本，不添加配置变更记录或其他实例的日志；无匹配行时不可导出。选中文本期间界面可能暂停刷新，此时导出的是屏幕上已显示的内容，而不是尚未显示的新行。切换实例或页面、运行代次变化、无权限或登出后会丢弃旧视图。导出只使用浏览器已收到的数据，不新增日志接口；权限撤销前已经发送到浏览器的数据无法收回。日志仍可能包含未知敏感信息，分享前请检查并妥善保管；文件最多包含当前内存窗口的 200 行，不是完整日志或持久审计记录。

两个接口都使用现有同源认证，不在 URL 中放置令牌或会话凭据。轮询响应保留 `lines` 和 `runId`。流先发送 `snapshot`，再发送 `lines`；两者包含 `instanceId`、`runId` 和字符串数组 `lines`。大快照可能拆为一个 `snapshot` 和多个 `lines`，客户端按顺序替换和追加。缓冲窗口被追过时服务端重新发送快照；重连也从新快照开始，不使用 `Last-Event-ID`，不保证补回窗口外日志。`heartbeat` 是空对象，`end` 只包含实例和运行代次。前端只接受当前实例、代次、导航及登录会话对应的响应，保留最近 200 行并在界面中筛选。

日志保存在内存中，按运行代次隔离，最近 200 行可通过轮询或流读取。完整行先移除已有的 ANSI 格式并遮蔽启动配置中已知的凭据；超过 16 KiB 的原始行会被丢弃并显示占位文字。此脱敏不能识别所有未知密钥、编码形式或其他敏感内容，也不是持久审计日志。配置变更仍由状态接口提供，不作为进程日志广播。

服务端限制总共 32 条流、每个实例 8 条，日志写入不等待网络。每个事件的日志文本分批，单次写入最多等待 5 秒；空闲时每 10 秒发送心跳，并在每个数据、心跳及结束事件前重新检查当前会话、实例和运行对象。认证撤销或运行对象变化后，下次检查终止流；已经通过检查、正在传输或已发送到浏览器的流数据和轮询快照无法撤回。关闭工作台会先唤醒日志流，再等待 HTTP 服务器退出。若连接不支持写入期限，实时接口会拒绝该连接，页面改用轮询。

本基线的删除操作要求先停止相关实例，导入、备份恢复及历史恢复要求先停止全部实例。成功删除后清除该实例的旧运行对象；成功替换配置后清除全部已停止的旧运行对象，即便新配置复用了相同实例 ID 也不会重新附着其日志。原有数据迁移和运行代次计数逻辑保持不变。

## 当前日志源和后续接入

默认构建使用进程内 frp：每次 `Start` 给该 `RuntimeConfig.RunID` 单独的日志接收器，再经过 manager 的逐行缓冲和脱敏。部分上游依赖仍可能使用进程级日志，隔离与关闭时序尚需真实并发和异常恢复验收。显式使用 `kurumi_external_runtime` 标签构建时仍可使用原来的外部进程后端。

## 账户权限接入和限制

本副本只有本机管理员令牌和会话，没有多账户或实例级授权。两个日志接口通过 `canReadInstanceLogs` 使用同一个接入点，当前仅重新检查本机管理员认证；它不是账户权限。流在每帧前重新检查认证。**在完成下列接线前，不得向受限账户开放这些接口或运行记录页面：**

1. 将 `canReadInstanceLogs` 替换为真实账户身份、实时会话校验和默认拒绝的实例授权，空授权列表不能代表全部实例。两个 GET 接口都必须经过同一权限检查，不能只在打开流时缓存身份；保持先取得 `a.mu` 再取得认证锁的顺序。
2. 为受限账户过滤状态响应中的实例、运行状态和配置变更记录，并保留可见实例的 `runId`、`generation` 供页面辨别代次。当前状态响应缓存不按账户分区，接入多账户时必须按权限安全重建或分区，不能把管理员缓存直接用于受限账户。
3. 为受限账户接通日志导航和已授权实例入口，同时保留其他页面及 API 的限制。退出、禁用和授权变更应使旧会话或旧授权失效；页面收到 403 或实例从状态中消失时清空现有日志。
4. 同时保留当前配置替换前停止实例及替换后清除旧运行对象的规则。任何未来允许保留运行对象的实现都必须明确退役已移除或重新引入实例的旧日志。

同源页面登录或登出时使用 `BroadcastChannel` 和 `storage` 通知其他页面清空旧视图；成功登录还会撤销请求中携带的旧会话，已建立的旧流在下次检查时结束。浏览器通知可能不可用或延迟，带管理令牌的外部客户端不受浏览器登出影响，并发登录也不能当作多账户隔离机制。账户实现必须在服务端处理会话替换、撤销和并发边界；不要依赖前端通知作为授权保证。
