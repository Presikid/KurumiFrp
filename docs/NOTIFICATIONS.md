# 事件通知

管理员最多可设置 8 个通知目标，每个目标可单独选择消息格式、完整的公网 HTTPS 地址、实例和已启用后台检查的节点状态、配置变更、登录限流和软件更新可用事件及可选签名；新目标默认关闭，登录限流和软件更新可用事件也默认不选择。已有的单目标设置会显示为“原有通知”，保持原来的启停状态和配置，不需要复制凭据。内建事件字段包含事件、时间和相应的实例 ID / 类型、节点 ID、配置版本、软件版本或连接对端 IP，不包含账户名、密码、令牌、配置或日志。自定义模板会发送其中填写的内容，请勿放入不希望目标收到的敏感信息。通知地址本身可能含令牌，目标服务及其代理能看到它；通知结果只表示目标是否接受请求，不能保证最终送达。

通用 JSON、Discord、Slack 和 ntfy 使用原有格式；Discord 和 Slack 填写对应的传入 Webhook 地址，ntfy 填写允许发布的完整主题地址。

## 状态通知筛选

每个目标可选“仅发送实例退出、启动失败和节点不可用”；默认关闭。此选项仅在选择“实例和节点状态”时生效：开启后发送 `instance.down`、`instance.start_failed` 和 `node.unavailable`，不发送 `instance.up` 和 `node.available`。实例退出包括主动停止，通知可能在实例资源清理完成前发出；节点不可用也可能由网络或授权问题引起，并不一定代表节点离线。其他已选择的事件及手动测试不受此筛选影响。

每个目标还可以选择状态通知的对象：全部实例和节点、全部本机实例、全部节点，或一个指定的本机实例。默认是全部实例和节点；选择单个实例不会发送节点状态。此范围与上述事件类型筛选同时生效，不影响其他事件或手动测试。

指定实例按实例 ID 匹配，不按名称匹配。实例删除后仍保留原筛选，不会自动改为全部；此前已经排队或发送的通知不能因删除而撤回。导入或恢复配置后，如出现相同 ID 的实例，该筛选仍会匹配，应核对通知目标和对象范围。

管理员接口 `GET /api/webhooks` 和 `GET /api/webhook` 返回 `statusProblemsOnly` 和 `statusScope`。保存时前者为布尔值；后者可为 `""`（全部）、`"instances"`、`"nodes"` 或 `"instance:<实例ID>"`。指定 ID 须为 16 位小写十六进制，但不要求实例仍存在；旧客户端省略字段会保留原值。更改筛选会使该目标旧队列失效，并尝试取消正在发送的消息；已经交给网络的数据无法撤回。

旧版本若不认识新字段，可能拒绝读取包含该字段的通知设置；回退前应为所有目标取消事件类型筛选、将对象范围恢复为全部并保存，其他新增设置还须按下文处理。

## 手动发送测试

管理员可以在配置中心对某个已保存地址的目标选择“发送测试”，包括已停用的目标。测试不受目标的事件选择影响，只发送给选中的目标；它不修改配置或修订号，也不计入页面上自动通知的成功、失败和丢弃统计。工作台同时只处理一个手动测试，请求使用现有的公网 HTTPS 检查、渠道格式、可选签名和 5 秒发送超时；手动测试不经过自动通知队列，因此可能与正常事件同时到达。

测试事件为 `webhook.test`，包含发送时的 UTC 时间，不包含实例、节点、版本或连接对端 IP。启用自定义 JSON 模板时，`{{event}}` 展开为 `webhook.test`、`{{at}}` 展开为时间，其余事件变量为空。模板不一定包含事件字段，或可能写有固定内容；请确认接收方不会把测试当作真实业务事件处理。页面显示目标是否接受请求，并不保证最终送达；连接失败、超时或取消时，接收方也可能已经收到消息，请先核对再重试。

测试使用开始时的配置修订；修订已变化时需要刷新后重试。发送期间目标地址、格式、签名、模板、事件选择或启停状态变化，目标被删除，工作台关闭或请求中断时会尝试取消发送，但已经交给网络的数据无法撤回。仅更改名称不会取消。测试结果不会回显地址、密钥、模板或远端响应正文。

## 可选请求签名

管理员可为每个目标单独设置或清除签名密钥；留空表示保留该目标的已有密钥。没有密钥时默认不签名，也不发送签名请求头。密钥为 8–1024 字节的 UTF-8 文本，不允许 ASCII 控制字符（U+0000–U+001F 和 U+007F）；空格也属于密钥的一部分。建议使用独立的高强度随机密钥，并通过安全渠道提供给接收方。页面和接口只显示是否已设置，不返回密钥内容。

管理员接口 `GET /api/webhooks` 返回各目标的配置概况及本次运行的结果计数，不返回地址或密钥；`POST /api/webhooks` 使用当前配置修订号和目标 ID 逐个新增、编辑、启停或删除。设置时 `signingSecret` 可替换密钥，`clearSigningSecret: true` 可清除；省略或留空密钥会保留该目标原值，同一请求不能同时设置和清除。`onLoginLimit` 和 `onUpdate` 分别控制两类新增事件，旧客户端省略时保留该目标已有值。原有 `GET /api/webhook` 和 `POST /api/webhook` 仍只操作“原有通知”，不会修改其他目标。

## 自定义 JSON 消息

每个目标可在选择“通用 JSON”时启用可选的 JSON 模板；默认关闭。模板须是一个合法 JSON 值，UTF-8 编码不超过 8192 字节、最多 16 层。可以使用对象、数组或其他 JSON 值；占位符只能放在字符串值中，可与文字组合。例如：

```json
{"event":"{{event}}","description":"实例 {{instanceId}} 的事件","time":"{{at}}"}
```

允许的占位符为 `{{event}}`、`{{at}}`、`{{instanceId}}`、`{{nodeId}}`、`{{kind}}`、`{{revision}}`、`{{sourceIp}}` 和 `{{version}}`；不适用于当前事件的字段替换为空字符串，配置版本也以十进制字符串替换。对象键不展开占位符；字符串或键中的 `{{`、`}}` 保留给占位符使用，不支持未知占位符、脚本或函数。模板先解析为 JSON，再替换字符串并重新编码，特殊字符不会改变 JSON 结构；编码后的请求体不超过 64 KiB。请求签名覆盖实际发送的最终字节。

模板可能包含敏感内容，与地址和签名密钥一样加密保存在本机，页面和接口不会返回模板原文。编辑时留空保留；可输入新模板替换，或勾选清除，不能同时替换和清除。只有通用 JSON 格式能启用模板；切换其他格式前需要停用它，已保存模板可保留以备以后使用。旧客户端省略相关字段不会清除或关闭模板，若格式与已启用模板冲突则保存失败。管理接口只返回 `hasJSONTemplate` 和 `jsonTemplateEnabled`，写入通过 `jsonTemplate`、`clearJSONTemplate` 和 `jsonTemplateEnabled` 完成。

## 节点后台检查

选择实例与节点状态通知，并为具体节点开启后台检查后，连续两次检查未成功会产生 `node.unavailable`，之后检查恢复会产生 `node.available`。首次成功不会产生恢复事件；工作台重启、节点设置变化或关闭检查会重置观察，不补发旧事件。事件只带本机节点 ID，不含地址、授权或远程实例信息。未成功可能由网络、DNS、证书或目标授权变化等原因导致，不代表节点或业务一定离线；检查繁忙时会跳过本轮。

## 登录限流和软件更新

选择登录限流后，登录失败次数达到现有限额，或实际登录尝试被并发占用、全局预算等限流拒绝，且该限流状态尚未通知时，才产生 `auth.login_limited` 事件；并发校验中的尝试也计入预算，因此这不表示账户被永久锁定。所有目标合计最多每分钟产生一次此事件；重复触发或冷却期间的事件可能被抑制，不会补发。限流通知的 `sourceIp` 是触发该事件的工作台网络连接对端 IP，并非此前所有尝试的来源；无法解析时省略。反向代理或 SSH 转发时，它可能是代理或本机 IP。工作台不读取 `Forwarded`、`X-Forwarded-For` 等转发头来推断来源。请选择可信目标接收 IP 地址。

选择软件更新后，现有的版本检查成功发现比当前版本更新且有可用安装包的版本时，才可能产生 `update.available` 事件；不新增定时检查，也不会仅因启用通知而联网。事件带 `version`，与软件更新页面的可用版本判断一致，可能包括预览版。工作台记录本次运行中最近 64 个已产生通知事件的版本，事件最多每五分钟一次；冷却期间的变化不会补发。检查失败不产生事件，并发检查中的较旧结果不会覆盖已处理的较新结果。限流和更新的去重记录在工作台重启后重置，启用事件不会补发已经观察到的状态。

设置密钥后，所有格式都在 `X-Kurumi-Signature-256` 请求头发送 `sha256=<64 位小写十六进制>`。计算方式为 `HMAC-SHA256(密钥的 UTF-8 字节, 实际发送的完整请求体字节)`；例如通用格式签 JSON 字节，ntfy 签文本字节，Telegram 签包含 `chat_id` 的最终 JSON，Gotify 签最终 JSON。接收方须在解析或重新序列化之前取得原始请求体，检查前缀、解码十六进制，再使用恒定时间比较验证；要求签名时应拒绝缺失、重复或格式错误的签名头以及验签失败的请求。请根据部署对读取的请求体设置大小限制。

以下 Go 片段展示验签核心（`header` 是该请求头，`body` 是原始请求体，`secret` 是配置密钥的 UTF-8 字节）：

```go
func validSignature(header string, body, secret []byte) bool {
    const prefix = "sha256="
    if !strings.HasPrefix(header, prefix) || len(header) != len(prefix)+64 {
        return false
    }
    signature, err := hex.DecodeString(header[len(prefix):])
    if err != nil {
        return false
    }
    mac := hmac.New(sha256.New, secret)
    _, _ = mac.Write(body)
    return hmac.Equal(signature, mac.Sum(nil))
}
```

该片段需要标准库的 `strings`、`encoding/hex`、`crypto/hmac` 和 `crypto/sha256`。签名只覆盖请求体，不覆盖请求方法或目标地址。通用 JSON 的 `at` 和各渠道消息中的时间是事件生成时的 UTC RFC 3339 时间，而非保证唯一的请求编号；即使它被包含在签名的请求体内，**签名和事件时间本身也不能防止重放**。需要防重放时，接收方须自行设计去重与有效期策略，并考虑时钟偏差及相同事件内容。

第三方渠道（包括 Telegram 和 Gotify）是否保留或验证自定义请求头由服务端决定，不能假定它们会验证签名。自建接收端或可信转发服务需自行启用验签；签名不会修改现有渠道的请求体格式或 Telegram 成功判定。

## Telegram

选择 Telegram 格式，并填写完整的 Bot API 地址，例如：

```text
https://api.telegram.org/bot<TOKEN>/sendMessage?chat_id=<CHAT_ID>
```

将占位符替换为 Bot 令牌和目标会话 ID。`chat_id` 可为数字 ID（包括负数）或 `@频道名`；地址只能包含一个 `chat_id` 查询参数，不支持其他查询参数。目标路径须以 `/bot<TOKEN>/sendMessage` 结尾；如使用自建 HTTPS 转发，须自行信任和保护该服务。发送时 `chat_id` 会从地址查询参数移入 JSON 请求体，与 `text` 一起提交；令牌仍在请求路径中。响应须为 HTTP 2xx 且 JSON 中的 `ok` 为 `true` 才计为成功。

## Gotify

选择 Gotify 格式，并填写包含应用令牌的完整消息地址，例如：

```text
https://push.example.com/message?token=<APP_TOKEN>
```

消息使用 JSON 请求体，包含 `title`、`message` 和 `priority`；标题为 `KurumiFRP`，优先级固定为 `5`。地址可以包含部署所需的路径和查询参数。HTTP 2xx 计为目标已接受请求。

## 存储与连接边界

通知地址可能包含令牌；每个目标的地址、签名密钥和 JSON 模板都使用本机数据密钥加密保存，不在页面再次显示，也不包含在配置导出、快照或加密备份中。导入和恢复忽略输入文件中的通知设置，保留全部本机目标，并在数据密钥变更时逐项重新加密这些内容；迁移失败会中止导入或恢复。其他设备需单独配置。加密不能阻止有本机文件和账户权限的人员读取这些内容。

所有渠道复用相同的公网地址检查：仅使用 HTTPS，不使用系统代理、不跟随重定向；发送时重新解析 DNS，拒绝含非公网 IP 的结果并直接连接已检查的地址，TLS 仍校验主机名。连接错误和响应内容不会回显到状态或错误消息。一个有界队列最多暂存 64 个事件，每个事件最多分发给 8 个目标；单个目标发送失败后仍会继续其他目标。发送由一个工作线程依次进行，每次最多等待 5 秒，慢目标会延迟后续目标。队列满时会丢弃；设置变更、关闭或中断可能使消息丢失，不自动补发。地址、密钥或其他通知设置变更后，该目标的旧队列不会使用新配置，其他目标不受影响；已经发往旧目标的请求会尝试取消，但已经交给网络的数据无法撤回。每个目标显示本次运行的成功、失败、丢弃数量和最近结果；更改地址、密钥、格式、事件或启停状态会重置该目标计数，仅更改名称不会重置。

旧版本若不认识新增的多目标、事件或模板字段，或不认识 Telegram、Gotify 格式或签名密钥字段，会拒绝读取该通知设置并保留原文件。需要降级时，应先删除全部新增目标、停用并清除原有通知的 JSON 模板、取消两项新增事件，再根据目标版本支持情况停用原有通知、清除地址与签名密钥，并将格式切回旧版本支持的通用 JSON 后保存；仅停用通知或清除地址并不会改变格式。
