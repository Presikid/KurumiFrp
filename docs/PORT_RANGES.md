# TCP/UDP 成对与端口范围创建

规则管理页的“批量 / TCP+UDP”接受逗号分隔的端口和递增范围，例如本地 `8000-8002,8010` 对应远端 `6000-6002,6010`。固定端口按展开顺序一一配对；重复、重叠、倒序、越界、两边数量不等或规则总数超过 512 条都会拒绝整批。单端口单协议使用原名称；多端口名称追加 `-本地端口`，TCP+UDP 成对创建再追加 `-tcp` 或 `-udp`。生成名称超长、名称或端口冲突也会拒绝整批。生成后的普通规则各自独立，可编辑、启停和删除；现有批量启停仍作用于选中的规则草稿。

远端只填 `0` 表示请求 frps 动态分配，支持单条 TCP/UDP 规则和单协议批量；每条规则分别请求分配。TCP+UDP 成对创建必须使用固定端口，不能保证两次动态分配得到相同端口。草稿中的 `0` 不是实际端口。只有当前配置修订、当前运行代次和已应用规则签名一致，状态来源报告运行中，且返回有效的非零端口时才显示最近观察到的动态端口。状态报告运行中但端口缺失、无效或同时报告错误时返回 `portPending` 并显示端口待确认；其他不可用、未应用和停止状态也不能证明分配结果。页面隐藏或状态请求超过 15 秒后会丢弃旧观察；链路检测报告是标有时间的快照，不会自动刷新。所观察的端口仍可能在重新注册后改变，注册状态不证明公网可达。

预检使用既有完整协议校验：检查同一实例的规则名、按客户端用户前缀计算的同服务端代理名，以及已启用的同协议固定远端端口。停用规则的固定端口不占用，后续启用时仍会校验；动态端口不作为固定端口冲突。校验按配置的服务端地址和控制端口识别，不解析 DNS、不检查未登记客户端或远端其他进程，真实可用性由 frps 决定。

## 本机接口和数据格式

`POST /api/tunnels/batch` 使用现有 Host、Origin、会话认证和应用锁，JSON 字段为 `revision`、`name`、`instanceId`、`protocol`（`tcp`、`udp`、`tcp+udp`）、`localHost`、`localPorts`、`remotePorts`、`bandwidthKB`、`enabled`。例如：

```json
{"revision":8,"name":"game","instanceId":"0123456789abcdef","protocol":"tcp+udp","localHost":"127.0.0.1","localPorts":"8000-8001","remotePorts":"6000-6001","bandwidthKB":0,"enabled":true}
```

请求在克隆草稿中展开，并通过当前 `Store.commit` 一次校验和写入；成功返回 `ok`、`created`、新 `revision`，修订冲突返回 409，输入或保存错误返回 400。正常失败不会留下部分规则；断线或超时时客户端无法确定请求是否已经提交，应稍后刷新、核对草稿和修订，避免盲目重试。这是单个本机管理器的提交边界，不是跨进程、跨节点事务，也不能保证异常断电后的文件系统持久性。

新建 TCP/UDP 或切换到这两种协议的 `/api/save` 请求必须显式提供 `remotePort`；同协议的局部编辑可省略并保留旧值，`null` 不表示动态分配。数据库、导入和快照中的 TCP/UDP 规则必须显式包含非 `null` 的 `remotePort`；显式的 `0` 可从来源分支的格式 3 数据迁移。没有新增持久字段，格式 4 的迁移、历史、备份、修订号和现有协议字段仍由当前实现处理。早期只接受固定端口的程序可能拒绝包含动态规则的当前状态或历史快照；不要手工修改格式号或用旧程序覆盖数据，回退前须保护并处理全部相关快照与备份。

## 与其他 0.8 工作的接口

- **账号和权限：**当前只有本机令牌会话，没有账号、角色或细粒度授权；该接口当前与 `/api/save` 有同等的本机写入权限。合并账号工作时，需把它加入规则创建权限及审计上下文，在认证和授权后再进入同一修订锁；不能因页面隐藏入口而假定后端已授权。
- **Webhooks：**一次成功的批量创建调用一次 `Store.commit`，由既有回调产生一次配置变更事件；验证或保存失败不会发出该事件。通知队列有容量限制，不能将一次提交等同于恰好一次远程投递。
- **节点：**此接口只操作本机工作空间；实例的上游服务器地址不代表节点管理权限。当前没有节点代理或远程批量接口。未来远程执行应在目标节点授权，并向目标节点一次提交完整批次及该节点的修订号；不能逐条保存后宣称整批原子，也不提供跨节点原子性。
