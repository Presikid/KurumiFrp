# 实时代理注册状态

KurumiFRP 在启动本机 frpc 时自动创建仅监听 127.0.0.1 的临时 frpc Web API。每次启动使用随机端口与独立随机密码，端口和密码不作为用户配置持久化。管理器仅通过固定本机回环地址发起短超时 HTTP 请求，禁用代理与重定向；仅已验证的管理会话可使用 `GET /api/registration`。

在「连接看板」中展示以下互相独立的状态：

- 配置意图：期望启用/停用。
- 进程状态：已启动、已退出或未启动。
- 代理注册：已注册、注册中、注册失败、状态不可读取、等待应用、待应用停用等。

已注册仅表示 frpc 内部报告该代理正在运行，并不意味着公网用户能连接，也不等同本地目标的 TCP 探测结果。stcp-visitor 不出现在 frpc 的代理状态接口中，所以明确标记「Visitor 未监测」，不能臆测成功。

如果保存了草稿而没有重启，前端会提示状态反映旧运行配置；原运行配置的名称、类型与是否启用在进程启动时单独捕获。不会因修改草稿而覆盖这些信息。敏感字段不进入前端；错误文本做内存秘密遮蔽、控制字符过滤和长度限制。

接口独立于普通 `GET /api/state`，最多并发 8 次回环查询；每次查询有 2 秒限制。不会访问 frps 的远程管理 API，不向公网发送管理密码，也不会给用户开放 frpc 管理端口。

## 验收方法

```sh
gofmt -l cmd internal web
go vet ./...
go test ./...
go test -race ./...
python3 scripts/core-smoke.py ./kurumi
```

建议人工再验证三个场景：正确的 frps 上启动 TCP 规则后显示「已注册」；使用冲突的远端端口出现「注册失败」；保存新草稿但不重启，不能把旧进程状态说成新配置的状态。UDP、HTTP、HTTPS、STCP 则采用同一个 frpc 官方状态接口；Visitor 仅显示「未监测」。

该功能依赖「本地服务连通性探测」PR 的代码，且不改变安装器、数据目录及持久化格式。
