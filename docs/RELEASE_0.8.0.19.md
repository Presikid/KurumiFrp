## Bug 修复

- 正常卸载时在完成提示前尝试清除维护标记；一次卸载最多尝试一次，异常提前退出仍保留原有收尾路径和失败提示。
- Linux 更新器识别 DEB 安装时检查实际包状态，不再仅凭查询成功就把配置残留当作已安装；不明确的安装状态会停止自动选择。
- 用户核对实例操作时，如刷新已观察到账户或权限变化，则保留待核对记录，要求重新确认。

## 已知限制

Windows 强制终止或断电仍可能留下维护标记。标记尚无事务标识；首次清理前若已被其他维护操作替换，无法证明其归属。卸载收尾失败的提示仍出现在标准完成提示之后，静默且抑制消息时可能不可见；原有“部分组件未卸载”提示的全部原因尚未确认。

Linux 更新仍可能在请求准备或监听期间遗漏请求，RPM 升级也可能改变服务状态。包格式同时登记为已安装、缺少查询工具或旧版 dpkg 查询故障时，仍无法可靠证明当前二进制属于哪种包。

实例操作记录的跨标签页读取与删除不是原子操作；浏览器尚未处理的身份变化也无法由本次核对检查获知。浏览器存储不可用时，提示只保存在当前页面。

本次通过 GitHub Actions 打包，尚未完成实际安装、升级和卸载验收。Windows 安装包未签名；macOS 仅编译源码，不提供安装包。此前实例操作修复见 [0.8.0.18 发布说明](https://github.com/Presikid/KurumiFrp/releases/tag/v0.8.0.18)。
