## Bug 修复

Linux 原生包安装或手动升级时，如果更新监听 `kurumifrp-updater.path` 已被明确屏蔽，安装脚本会跳过该监听的启用并继续原有的工作台安装步骤；查询失败或其他启用失败仍会报告。屏蔽未解除前，该监听不会由本次步骤启动。

本次还修正项目维护方向与文档，移除过时的用户套餐、订阅和支付计划。工作台沿用 [0.8.0.20](https://github.com/Presikid/KurumiFrp/releases/tag/v0.8.0.20) 的单密码访问方式，不提供账户、分组或套餐管理。

## 已知限制

本次只处理明确屏蔽的更新监听。升级前即使监听被屏蔽也可能仍在运行，现有升级流程会停止它，本次不恢复这种状态；原先禁用或停止的服务也仍可能被启用或启动。管理员并发更改屏蔽状态时，检查与启用之间仍有竞争。Linux 更新请求在准备或监听期间仍可能遗漏。

Windows 安装或卸载异常中断仍可能遗留维护标记；此前“部分组件未卸载”提示的全部原因尚未确认。旧版账户文件保留、旧 frps 认证转换及跨数据密钥导入的限制见 [0.8.0.20 发布说明](https://github.com/Presikid/KurumiFrp/releases/tag/v0.8.0.20)。

本次通过 GitHub Actions 构建和打包，尚未完成真实 systemd 安装升级、浏览器、协议和 Windows 卸载验收。Windows 安装包未签名；macOS 仅编译源码，不提供安装包。
