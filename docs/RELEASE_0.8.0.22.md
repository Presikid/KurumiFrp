## Bug 修复

- 修复上一次使用自定义回环地址的工作台正常退出后，安装版快捷方式因旧地址不在自动端口范围而无法重新启动的问题。自动启动会选择可用的默认回环端口；旧地址格式无效、不是回环地址或无法读取时，仍会报告错误。发现已有锁时，不会用推测的地址打开现有工作台。
- Linux 原生包在没有 `deb-systemd-helper` 的 systemd 系统上安装或升级时，如果工作台服务已被明确屏蔽，跳过该服务的启用和启动；状态查询失败仍会报告。使用 Debian helper 的路径保持原来的行为。
- 包含 [0.8.0.21](https://github.com/Presikid/KurumiFrp/releases/tag/v0.8.0.21) 对被屏蔽的更新监听的修复。控制面板沿用 [0.8.0.20](https://github.com/Presikid/KurumiFrp/releases/tag/v0.8.0.20) 的无账户、单密码方式。

## 已知限制

自定义地址的自动回退不会自动打开仍在运行的旧地址工作台，也不修复针对 IPv6 地址的停止或卸载维护操作。Linux 升级前即使服务被屏蔽也可能仍在运行，现有升级流程会停止它，不恢复这种状态；其他禁用或停止状态仍可能被改变，检查和启用之间仍可能与管理员操作发生竞争。Linux 更新请求在准备或监听期间仍可能遗漏。

Windows 安装或卸载异常中断仍可能遗留维护标记；此前“部分组件未卸载”提示的全部原因尚未确认。旧账户文件保留、旧 frps 认证转换及跨数据密钥导入的限制见 [0.8.0.20 发布说明](https://github.com/Presikid/KurumiFrp/releases/tag/v0.8.0.20)。

本次通过 GitHub Actions 构建和打包，尚未完成真实 systemd 安装升级、浏览器、协议和 Windows 卸载验收。Windows 安装包未签名；macOS 仅编译源码，不提供安装包。
