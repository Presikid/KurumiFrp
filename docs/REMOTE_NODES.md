# 远程节点只读状态

此功能用于从一个工作台按需查看另一个工作台的实例名称、类型和进程状态。目标工作台必须支持本功能，且由目标管理员主动生成独立只读授权。授权不允许修改配置、启停实例或读取日志，进程运行也不代表代理已注册或业务可达。每个目标工作台目前只有一个共享授权；重新生成或撤销会影响所有使用该授权的控制端。

## 连接前准备

1. 在目标工作台的「节点管理」中选择「生成 / 更换授权」。新授权只显示一次；原授权立即失效。通过安全渠道把它交给获准的控制端。显示前断线或关闭页面时，新授权可能已经生效而无法找回，应重新生成并更新所有控制端。
2. 管理员在目标设备配置可信 HTTPS 反向代理。只转发 `GET /api/node/summary` 到工作台的本机回环监听地址，其他路径应拒绝；将上游 `Host` 改成工作台实际的回环地址和端口。工作台本身不会对公网监听，也不会自动配置反向代理、防火墙、证书或 DNS。
3. HTTPS 地址的证书必须被控制端运行 KurumiFRP 的操作系统信任且匹配该地址。仅连接可信的代理，代理可看到只读授权和所返回的状态；保护代理配置、访问日志和网络边界。
4. 在控制端添加节点，填写 HTTPS 来源地址（不含路径、查询、片段或用户信息）和目标授权。保存后点击「核对地址」，确认列出的 IP 属于目标，再点击「检查状态」。更改 HTTPS 地址时必须重新填写授权，并重新确认解析地址。

例如，在具有有效证书和对应名称解析的 Nginx 中，可按实际端口与本机监听地址调整以下结构。证书文件和服务配置由目标管理员自行提供；不要把整个工作台或登录接口暴露出去。

```nginx
server {
    listen 443 ssl;
    server_name node.example.com;
    ssl_certificate     /path/to/fullchain.pem;
    ssl_certificate_key /path/to/private-key.pem;

    location = /api/node/summary {
        limit_except GET { deny all; }
        proxy_set_header Host 127.0.0.1:9000;
        proxy_pass http://127.0.0.1:9000;
    }
    location / { return 404; }
}
```

如果目标工作台使用自动端口，需要根据实际监听端口更新两个 `9000`。应另外限制可访问代理的网络来源，并确认代理不会把 Authorization 请求头写入日志。控制端只允许经 HTTPS 检查，使用正常证书校验，不使用系统代理、不跟随重定向；不支持自定义 CA 文件或关闭校验。首次检查前必须确认域名当前解析出的全部 IP；若解析结果的 IP 集合发生变化，检查停止且不发送授权，需要再次核对确认。实际连接直接拨打已确认 IP，TLS 仍验证原 HTTPS 地址的主机名，避免解析后再次查找时被替换。允许内网和回环地址；最多确认 16 个不同 IP，空结果或过多地址会被拒绝。

服务商使用轮换或动态 DNS 时，合法变更也需要重新确认，这是防止地址变化被悄悄接受的取舍；顺序变化和重复记录不影响比较，只监控最终 IP 集合，不监控未改变最终地址的 CNAME 或 TTL 变化。确认前请独立核对 IP 归属；已确认 IP 上的服务如果被替换，仍依靠 HTTPS 证书校验识别，不保证该服务本身可信。

连接超时、拒绝授权和不受信任证书不会被显示成在线。每次检查最多等待 5 秒，只在用户操作时发起，最多并发 4 次；结果显示检查时间，不是持续在线监控。最多保存 32 个远程节点。

## 撤销与数据保护

在目标工作台撤销授权才能终止后续访问；从控制端删除节点只移除该控制端保存的记录，不能代替目标撤销。撤销或轮换会等待已获准的摘要写入完成或失败，然后才发布新授权状态；每个摘要有两秒写入期限，其他配置锁或存储操作仍可能增加等待时间。已交给系统网络栈或反向代理缓冲的响应仍可能在撤销后到达，无法撤回。目标上已经开始读取的检查也可能完成。生成或保存结果在断线时不确定，请刷新并核对，再决定是否重试；生成授权的不确定结果需要重新生成。

目标仅保存授权的 SHA-256 校验值。控制端使用本机数据密钥加密保存目标授权，绝不通过节点列表接口返回它；此加密依赖本机文件和账户权限，不能防止同一系统账户或管理员读取本机数据。节点设置和授权不进入配置导出、快照或加密备份。导入配置和恢复备份保留本机节点及本机只读授权，并在数据密钥更换时重加密控制端授权；其他设备恢复备份后需要分别重新添加节点和授权。Webhook 设置继续保留。

节点设置添加到格式 4 单文件时，旧程序若不能识别 `nodes` 字段应拒绝读取，不能忽略字段后写回；不要以旧程序覆盖新数据。缺损或无法解密的本机节点设置会导致启动拒绝并保留原文件，需先保护原件再排查。

## 接口与账号集成边界

`GET /api/node/summary` 只接受目标生成的独立只读 Bearer 授权，返回协议版本、工作台版本以及实例 ID、名称、类型和进程状态；不返回令牌、规则、配置、日志或错误详情。它不能使用本机登录会话或本机访问令牌替代授权。目标检查授权和读取状态在同一把锁内，生成/撤销后新请求立即使用新状态。

`GET /api/nodes`、`POST /api/nodes`、`POST /api/nodes/check`、`POST /api/nodes/resolve` 和 `POST /api/nodes/confirm` 是本机管理接口，适用现有 Host、Origin 和本机身份校验。列表返回不含明文授权的记录快照标识；解析和检查先验证标识，返回前再次验证，地址确认还会重查 DNS 和配置修订号。网络检查不持有配置锁，实际连接只拨打已确认地址。节点设置变更不会触发实例配置变更 Webhook，也不操作目标配置。

目标摘要和授权变更的锁顺序为先节点授权门闩、后应用锁；状态复制完成后释放应用锁，在受限写入期限内刷新摘要，再释放门闩。撤销成功表示此前被允许的响应已交给底层发送或写入期限已到，而不是保证网络或代理中没有排队字节。工作台若无法为响应设置写入期限，会拒绝该摘要请求。后续改变本机只读授权的代码也必须遵守相同顺序。

当前基础版本只有完整本机管理会话。合并多账号后，所有本机 `/api/nodes` 管理、查看和检查接口必须在服务端限制为管理员，不能因隐藏入口而放行受限账号；独立的 `/api/node/summary` 只能按上述只读授权访问。待实现逐节点/逐实例授权前，不能把此功能宣称为账号隔离的远程管理。
