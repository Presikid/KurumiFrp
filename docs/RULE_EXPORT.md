# 批量导出规则配置

管理员可在规则列表选择规则并导出 ZIP 或 TOML。切换筛选会保留已选规则，工具栏显示总数和筛选外数量；“选择当前筛选”只影响当前可见规则，可用“仅保留当前筛选”移除隐藏选择，或清空全部选择。批量启停、删除和导出都会处理全部已选规则，确认时会再次显示筛选外数量。请求绑定当前草稿修订号；草稿变化后需刷新并重新选择。ZIP 不加密，TOML 中包含明文客户端认证令牌、所选规则的配对密钥、HTTP 密码、SOCKS5 插件密码和自定义 HTTP 头值，应像密码一样保护文件并避免公开分享。

每个所属客户端生成一个 `frpc-<实例ID>.toml`，文件注释标明客户端名称、ID 和草稿修订号。每份文件包含该客户端的连接配置和属于它的所选规则，不包含未选规则；所选停用规则保留为 `enabled = false`。应使用支持该字段的 frp 客户端，当前内置核心支持。导出草稿不会启动实例，也不代表代理注册成功或服务可达。

Unix 套接字规则的连接式和 HTTP 自动健康检查由 KurumiFRP 内置客户端实现。官方 frpc v0.72.0 仅在配置了本地端口时启动健康监测，而导出的 Unix 插件不设置本地端口，因此该客户端不会执行这些检查；导出文件会加入提示。其他客户端的行为需自行确认，不能仅凭 TOML 中有健康检查字段认定检查正在运行。

管理员也可以通过现有的 `POST /api/tunnels/export` 接口直接导出单份 TOML：请求 JSON 使用 `revision`、所选规则 `ids`、`confirmed: true` 和 `format: "toml"`。所选规则必须全部属于同一个客户端，接口返回 `application/toml` 附件 `frpc-<实例ID>.toml`。不填写 `format` 或填写 `"zip"` 时仍返回原有 ZIP，跨客户端规则须使用 ZIP。TOML 同样包含明文认证信息，必须妥善保管；版本、权限和回退链检查与 ZIP 导出相同。

XTCP Visitor 的回退目标须同时选择，并属于同一客户端；已启用的 Visitor 不能指向已停用的目标。停用的 Visitor 也须包含完整、无循环的回退链，避免后来启用时缺少依赖。若依赖不满足，整个导出会报错，不会生成不完整文件。

TOML 中字符串的花括号以 Unicode 转义，避免 frp 的 Go 模板处理把原始值当作模板执行；TOML 解码后仍是原值。最多选择 512 条规则，解压后的配置内容最多 16 MiB。文件名使用系统生成的客户端 ID，而不使用实例名称作为路径。
