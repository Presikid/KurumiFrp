# 实例每周定时计划

管理员可在实例卡片的“定时计划”中添加最多 64 个每周事件；每项指定星期、时分和启动或停止。同一实例的同一星期时分只能有一项。时间按计划填写的固定 UTC 偏移计算，例如北京时间填 `480` 分钟。偏移不会随系统时区或夏令时自动变化，需手动调整。保存后从下一分钟的事件开始生效。

计划属于工作台，而非创建计划的账户。只有管理员能创建、启用、修改或删除，但创建者之后被降权、删除或更改密码不会自动撤销已启用计划。启用计划表示允许工作台在所列时间启动或停止该实例，包括停止已经运行的实例。

工作台只有运行时才执行事件；关闭、休眠或离线期间错过的事件不会补发。重新启动后只处理后续事件，不会自动推断当前应运行的状态。时钟向后调整时，已记录的时间不会再次执行；在时钟追上已记录时间前，事件可能不执行。系统时间应保持准确。

本地或远程手动启动、停止、重启通过初步检查后，会先持久暂停该实例计划；即使后续操作失败也不会自动恢复。实例或关联规则草稿变更、核心切换、冲突、操作失败或结果未知也会暂停计划。请检查实例状态、配置和计划，然后由管理员明确勾选恢复。校验配置不会暂停计划。计划启用时，即使暂停也优先于实例的“工作台启动时自动恢复”；关闭或删除计划后，原自动恢复设置重新生效。

事件执行前先保存执行记录，并复用实例操作预约；同一实例的操作不会并发。实例已处于所需状态时该事件不改变进程。计划启动先检查配置，验证未完成或时间、配置发生变化时不会延迟启动；接受启动不保证代理注册或网络可达。事件记录共用配置文件的串行写入，存储较慢或同一分钟事件很多时，操作可能因超过事件分钟而暂停。外部核心的启动请求被接受也不证明进程之后仍存活，应查看实例状态。停止操作一旦受理，会完成对当时预约的进程的停止。

正常关闭工作台时会停止托管实例。若上次操作记录尚未完成或有运行中的计划实例未能确认清理，下次启动时计划暂停，须人工核对。兼容的外部核心在工作台异常退出后可能仍存活；产品入口保留 `manager.lock`，必须先确认旧工作台和 frp 进程状态，不能盲目删除锁。直接嵌入 manager 包的调用方须自行保证进程唯一性和异常清理。无法写入执行记录时不会执行该事件，计划在本次工作台运行期间停止调度并显示错误；修复存储并核对后重新保存计划。计划沿用工作台已有的文件持久化方式，突然断电或文件系统故障时不能保证最近一次保存的目录项已落盘，应在恢复后核对计划和实例状态。

配置导出和加密备份包含导出范围内实例的当前计划，不包含计划的历史版本。导入配置或恢复加密备份会替换当前计划，导入的计划统一暂停；恢复历史快照保留仍存在实例的当前计划但将其暂停，不再存在实例的计划删除。导入或恢复后须检查再启用。
