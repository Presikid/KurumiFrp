# TCP 规则的 SOCKS5 客户端插件

开发中的 TCP 规则可选择 SOCKS5 插件，使用 frp 客户端所在机器发起 SOCKS5 CONNECT 连接。插件需要用户名和密码，二者均为 1–255 字节的 UTF-8 文本且不能包含控制字符；不接受无认证模式。短密码容易被猜测，建议使用随机密码；编辑器可在本地生成并显示供复制，保存后不会回显。插件不按来源限制认证尝试。该插件不提供 SOCKS5 BIND 或 UDP ASSOCIATE。协议本身不会加密用户名、密码和代理流量；使用者可访问客户端网络，需自行保护访问链路和公开端口。

SOCKS5 目标不使用本地地址、端口或 Unix 套接字，不能同时设置本地目标探测、代理健康检查或 PROXY 协议。规则仍可设置 TCP 远端端口、frp 传输加密、压缩及服务端限速；客户端限速暂不可用。每条规则最多同时处理 512 条已分派的 SOCKS5 连接，每个内嵌客户端实例最多处理 2048 条；超过上限的连接会被关闭。保存只更新草稿，重新应用客户端实例后才会生效。受限内嵌核心的插件生命周期与协议互通仍须实际验收；不能仅根据保存成功认为代理已经可用。

规则使用 `pluginType: "socks5"`、`pluginUser` 和 `pluginPassword`。保存请求首次启用插件时须提交实际密码；编辑同一插件时省略 `pluginPassword` 或传空字符串会保留原密码，提交非空值会更换密码。状态响应不返回密码或密文，只以 `hasPluginPassword` 标记是否已有密码。字段不能使用 JSON `null`。切换到其他目标时须在同一个保存请求中设置 `pluginType: ""`、`pluginUser: ""` 和 `clearPluginPassword: true`，再按新目标填写地址；清除选项不能与新密码同时使用。插件仍启用时不允许清空密码。

TOML 导入支持 `plugin.type = "socks5"`、`plugin.username` 和 `plugin.password`，要求 TCP 规则及上述凭据限制，不能同时携带 `localIP` 或 `localPort`。无法保留的插件字段和无认证配置会阻止导入，不会被静默丢弃。沿用现有模板安全规则，输入文本中的原始 `{{` 会被拒绝；导出时会将花括号转义，解码后保留原值。包含已启用 SOCKS5 规则的配置预览以未加引号的 `plugin.password = <redacted>` 隐藏插件密码，预览不是有效 TOML，不能运行或导入；实际密码为 `<redacted>` 时，确认导出的 TOML 仍会将其作为有效字符串写出。确认导出的单客户端 TOML 或 ZIP 包含明文密码，应像凭据一样保管。

插件密码独立加密保存在配置中，随规则复制、历史快照及加密备份保留；导出配置还包含解密密钥，因此也属于敏感文件。导入或启动时会校验已保存密码是否能解密且符合约束；出错时拒绝处理，保留原文件。缺少插件字段的旧配置保持原有行为；旧版严格读取器可能拒绝包含新字段的配置，降级前应保护当前数据和历史快照。
