# 版本约定

项目版本使用 `a.b.c.d` 四段数字，当前版本以仓库根目录的 `VERSION` 为准。标签使用 `v` 前缀，例如 `v0.7.1.20`。各段取值为 0–65535，以兼容 Windows 安装程序版本字段。

- `a`：超级大版本，由项目负责人决定；推进时 `b.c.d` 归零。
- `b`：功能大版本，由项目负责人决定；推进时 `c.d` 归零。
- `c`：一个功能板块中的小板块完成时推进；推进时 `d` 归零。
- `d`：每次发行默认推进一位；普通提交不单独推进版本号。

并行 PR 可能基于相同的旧版本；整合时以最新目标分支为准，调整版本号并同步程序、安装包、界面和发布说明。`VERSION` 和 `internal/version/version.go` 必须一致。

版本比较按数字逐段进行；为了识别旧版本，更新器将旧三段标签视为末段为零。已发布的 0.6.0 更新器不能识别四段标签，首次升级需要手动安装对应的原生包。新修改直接提交 `main`，不新建 PR；GitHub Actions 随主分支推送触发，构建并核对发行附件。版本尚未发布时会创建对应的 Release，也可以在需要时手动运行发布流程；已存在的发行版不会被覆盖。

发布说明直接写更新内容，不重复发布标题中的产品名和版本号。
